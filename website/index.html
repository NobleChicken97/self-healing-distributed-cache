    The ledger.

    Write once through the node under inspection; the primary stores it, a replica warms up, and every node answers. Reads that miss a freshly-restarted primary are served from replicas — then healed. Dashboard writes default to a one-hour TTL so experiments clean up after themselves.

    Two drills that prove it.

    Quorum, the strict mode

    Writes wait for a majority; reads answer only from a majority, newest version wins. Kill the majority and reads honestly fail 503 instead of lying.

    version, acks and serving node appear here.

    The fifteen-second key

    One key, fifteen seconds of life. Watch it vanish on every node at once — absolute expiries replicated, drift under a millisecond.

    The wiring.

    Same-origin by design: this page is served by the cache nodes themselves, so every call below is a plain fetch with no proxy, no keys, no ceremony. Point your own tools at any node.

    endpoint ledger
    POST /setwrite a key (JSON: key, value, ttl_ms)
    GET /get?key=read, with replica fallback + healing
    DELETE /delete?key=delete, replicated
    POST /quorum/set · GET /quorum/getmajority-ack writes, majority reads
    GET /ring/info · /cluster/infotopology and membership
    GET /health · /metricsliveness and counters
    POST /rebalance · GET /rebalance/statusmigrate and inspect

    Run it yourself

    curl -X POST http://NODE:8080/set \
  -H 'Content-Type: application/json' \
  -d '{"key":"hello","value":"mesh","ttl_ms":60000}'

curl 'http://NODE:8080/get?key=hello'
