WHAT IT DOES

Features

Consistent Hashing

Keys distributed via hash ring with 150 virtual nodes per physical node. Adding or removing a node moves only ~1/N keys.

Async Replication

Each key replicated to one additional node. Writes are asynchronous for low latency while maintaining fault tolerance.

SWIM Gossip Detection

Nodes detect peer failures automatically via hashicorp/memberlist SWIM protocol. Detection within ~2 seconds.

Automatic Failover

Requests for dead node's keys are automatically redirected to replicas. Health-aware routing skips known-dead nodes immediately (~2.5ms).

Zero-Downtime Rebalancing

Pull-before-drop protocol ensures no window where a key is absent from all nodes during topology changes.

TTL Consistency

Absolute expiry timestamps replicated across all replicas. Less than 1ms drift between nodes for synchronized expiry.

API Reference

API Examples 
# Set a key with TTL
$ curl -X POST http://localhost:8080/set \
  -H "Content-Type: application/json" \
  -d '{"key":"hello","value":"world","ttl_ms":60000}'
{"status":"ok"}

# Get the key (works from any node)
$ curl http://localhost:8081/get?key=hello
{"key":"hello","value":"world"}

# Check cluster health
$ curl http://localhost:8080/health
{"status":"healthy","alive_nodes":3}

# View operational metrics
$ curl http://localhost:8080/metrics
{"entry_count":42,"memory_usage":1024}

# Trigger manual rebalance
$ curl -X POST http://localhost:8080/rebalance
{"status":"rebalance started"}

# Quorum write (stronger consistency)
$ curl -X POST http://localhost:8080/quorum/set \
  -H "Content-Type: application/json" \
  -d '{"key":"critical","value":"data"}'
{"status":"ok","acks":2,"version":1}
